# Impeccable — Design Context

## Users

**Who**: A mixed audience spanning developers writing agent skills from scratch and less-technical users who want to browse, fork, and customize existing skills without touching raw YAML. They come from different comfort levels with code but share a curiosity about AI agents.

**Context**: People arrive wanting to experiment. Some are at a desk deep in an IDE, others are on a laptop exploring what's possible. The mood is exploratory and low-pressure — this isn't mission-critical infrastructure, it's a creative workshop.

**Jobs to be done**:
1. Author structured skill files (YAML/Markdown) through a guided, form-like experience
2. Browse and search a catalog of existing skills, then fork and customize them
3. Define tool schemas, system prompts, and reference materials, then export a complete skill package

## Brand Personality

**Three words**: Inventive · Fluid · Expressive

**Voice**: Encouraging but not patronizing. Speaks plainly, avoids jargon walls, trusts the user to figure things out through interaction rather than documentation. Celebrates the act of making — the interface itself should feel like a creative tool, not an admin panel.

**Emotional goal**: Playful experimentation. Low stakes, easy to try things, undo freely, remix without guilt. The feeling of sketching on a napkin — but the napkin turns into production-ready output.

## Aesthetic Direction

**Visual tone**: Organic and warm. Textured surfaces, approachable forms, human touches. Not slick-corporate, not scrappy-terminal. Think: a well-worn woodworking bench with good tools hung on the wall — everything has a place, everything is reachable, and the material itself is pleasant to touch.

**Inspiration**: Linear's density and keyboard-first interaction model, but warmer. Information-rich without feeling cold. Fast navigation, minimal chrome, content-forward layouts where the skill being authored is always the protagonist.

**Anti-references**:
- Generic SaaS landing pages with stock illustrations and "Get Started Free" hero sections
- Cluttered enterprise dashboards drowning in navigation and sidebars
- The cyan-on-dark, gradient-text AI aesthetic of 2024

**Theme**: Both light and dark, user-toggleable. Default should be derived from system preference. Dark for the focused late-night session; light for the daytime browse-and-explore session.

**Color direction**: No forced palette — design what fits the organic/warm direction. Lean toward earthy, muted tones with a single vivid accent that feels hand-picked rather than algorithmic. Avoid cold blues and sterile grays as dominant surface colors.

**Typography direction**: Pair a characterful display face with a highly legible body font. The display font should feel slightly unexpected — not the obvious "creative tool" choice. The body font must hold up at small sizes in dense layouts.

## Design Principles

1. **Content is the interface.** The skill being authored should dominate the viewport. UI chrome exists to serve the content, not to brand the product.

2. **Progressive disclosure, not progressive hiding.** Start with the essential fields. Let users pull in complexity as they need it — advanced tool schemas, reference files, export options — without burying those features behind three clicks.

3. **Texture over flatness.** Subtle surface variation, shadow, grain, or color shifts that make the interface feel physical. Not skeuomorphic, but not the featureless white plane of a generic SaaS either.

4. **Fast by default.** Keyboard shortcuts, instant search, no loading spinners for local operations. The interface should feel like it responds before you finish the thought.

5. **Remix culture.** Forking, duplicating, and experimenting should feel as natural as breathing. Every skill is a starting point, not a finished product.

## Technical Constraints

- **Framework**: SvelteKit + Svelte 5 (Runes mode enforced)
- **Styling**: Tailwind CSS v4
- **Content**: mdsvex for Markdown/Svx processing
- **Icons**: Bootstrap Icons
- **Deployment**: Static adapter (SSG)
- **Accessibility**: Standard best practices — good contrast ratios, keyboard navigable, semantic HTML, `prefers-reduced-motion` respected. No formal WCAG compliance target but AA contrast as a floor.
