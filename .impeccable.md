# Impeccable — Design Context

## Users

**Who**: A mixed audience spanning developers writing agent skills from scratch and less-technical users who want to browse, fork, and customize existing skills without touching raw YAML. They come from different comfort levels with code but share a curiosity about AI agents.

**Context**: People arrive wanting to experiment. Some are at a desk deep in an IDE, others are on a laptop exploring what's possible. The mood is exploratory and low-pressure — this isn't mission-critical infrastructure, it's a creative workshop.

**Jobs to be done**:

1. Author structured skill files (YAML/Markdown) through a guided, form-like experience
2. Browse and search a catalog of existing skills, then fork and customize them
3. Define tool schemas, system prompts, and reference materials, then export a complete skill package

## Brand Personality

**Three words**: Sharp · Electric · Inventive

**Voice**: Encouraging but not patronizing. Speaks plainly, avoids jargon walls, trusts the user to figure things out through interaction rather than documentation. Celebrates the act of making — the interface itself should feel like a netrunner's workbench.

**Emotional goal**: Playful experimentation with an edge. Low stakes, easy to try things, undo freely, remix without guilt. The feeling of hacking a system — but the system is yours and it wants to be hacked.

## Aesthetic Direction

**Visual tone**: Cyberpunk. Dark-first with amber phosphor accents on deep violet-black surfaces. Angular typography, hard edges, scanline texture overlays, terminal-style code previews, HUD-inspired data displays. Not the lazy cyan-glow-on-black AI cliché — this is warm amber, like old CRT phosphor or Blade Runner 2049's dusty orange palette.

**Key visual elements**:

- Scanline overlay (subtle repeating-linear-gradient on dark mode)
- Hard 2px border-radius (no soft rounded corners)
- Uppercase headings with wide letter-spacing
- Line numbers and blinking cursors in terminal previews
- Numbered feature indices (01, 02, 03)
- Dotted-line spacers in catalog rows
- Bordered magenta tag pills
- Amber glow (box-shadow) on interactive element hover

**Inspiration**: Blade Runner 2049's amber palette, Ghost in the Shell terminal screens, Linear's density and keyboard-first interaction, but warmer and grittier.

**Anti-references**:

- Generic SaaS landing pages with stock illustrations
- The cyan-on-dark, purple-to-blue gradient AI aesthetic of 2024
- Cluttered enterprise dashboards
- Lazy "dark mode with glowing accents" without texture or personality

**Theme**: Dark-first (cyberpunk demands it). Light mode available as a "daytime terminal" variant — warm off-white surfaces, same angular energy, same fonts, darker amber accent for contrast. User-toggleable with system preference detection.

**Typography**:

- Display: Chakra Petch — angular, geometric, Thai-script-inspired mechanical feel. Hard and distinctive without being decorative.
- Body: Rajdhani — angular but proportional, excellent legibility at small sizes, same geometric DNA as Chakra Petch.
- Monospace: System mono stack (SF Mono, Cascadia Code, Fira Code) for terminal/code elements only.

**Color system (OKLCH)**:

- Surfaces: violet-black (hue 285), depth via lightness steps
- Accent: electric amber (oklch 82% / 0.175 / hue 80) — phosphor display warmth
- Secondary: hot magenta (oklch 72% / 0.2 / hue 345) — for tags and secondary highlights
- Neutrals: all tinted toward violet (hue 285)
- Terminal: green text (hue 145), amber keywords (hue 80), magenta strings (hue 345)

## Design Principles

1. **Content is the interface.** The skill being authored should dominate the viewport. UI chrome exists to serve the content, not to brand the product.

2. **Progressive disclosure, not progressive hiding.** Start with the essential fields. Let users pull in complexity as they need it — advanced tool schemas, reference files, export options — without burying those features behind three clicks.

3. **Texture over flatness.** Scanlines, glow effects, panel borders, surface variation. The interface should feel like a physical piece of hardware — a diagnostic terminal, not a flat web page.

4. **Fast by default.** Keyboard shortcuts, instant search, no loading spinners for local operations. The interface should feel like it responds before you finish the thought.

5. **Remix culture.** Forking, duplicating, and experimenting should feel as natural as breathing. Every skill is a starting point, not a finished product.

6. **Cyberpunk Visuals, Human Copy.** The aesthetic must be strictly cyberpunk (sharp edges, terminal styling, heavy uppercase tracking, mono-fonts), but the text itself must be unambiguous, plain-English, and accessible to the simplest, non-technical users. Never use pretentious sci-fi filler (e.g., "System running in disconnected mode") or overly technical jargon (e.g., "Triggers", "Imperative phrasing"). Write like a human, style like a machine.

## Technical Constraints

- **Framework**: SvelteKit + Svelte 5 (Runes mode enforced)
- **Styling**: Tailwind CSS v4
- **Content**: mdsvex for Markdown/Svx processing
- **Icons**: Bootstrap Icons
- **Deployment**: Static adapter (SSG)
- **Accessibility**: Standard best practices — good contrast ratios, keyboard navigable, semantic HTML, `prefers-reduced-motion` respected. No formal WCAG compliance target but AA contrast as a floor.
